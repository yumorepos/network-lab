## Reproducible read-only experiment

The unchanged original ingestion path is `ingest/bts_t100.py` through
`ingest/transtats.py`. It already pulls table 293, but downloads one full
calendar year and would write to `data/parquet/t100`; this experiment **does
not call the production ingest runner**.

The new `scripts/stage_b_t100_pilot.py` calls the same official download
endpoint for the 2026 and 2025 year ZIPs, then filters the actual data to only
July in each year. It writes a separate disposable DuckDB database plus JSON
and operator/airport-direction CSV diagnostics to a supplied research directory.
The GitHub Actions job uses the temporary runner directory, not `data/`.

Reproduction (requires public TranStats connectivity):

```bash
python -m scripts.stage_b_t100_pilot --output-dir /tmp/networklab-stage-b
pytest tests/test_stage_b_t100_pilot.py -q
```

The checks cover required schema, nonnegative passenger and capacity counts,
positive departures, exact duplicates and key collisions, foreign-to-foreign
and US-touch scope, reporting-carrier versus brand uncertainty, and preservation
of origin/destination direction. The comparison preserves operator, origin and
destination and does not equate T-100 segment passengers to O&D demand.
Offline negative controls deliberately corrupt missing-column, negative-pax
and non-US-scope examples; they must be rejected.

**Unresolved controls:** The pilot does not yet join to a source-verified
airport-to-metro crosswalk and does not establish completeness of all foreign
carrier filings. The old 2025 comparison is also a currently revised extract,
not data available to an analyst as of July 2025. Do not use any month-to-month
or year-to-year difference to alter market verdicts under these limitations.

## Observed first-run result (2026-10-28 UTC)

Evidence: [isolated public-data job 40780561819](https://github.com/yumorepos/network-lab/actions/runs/40780561819),
which downloaded T-100 table 293 year ZIPs for 2026 and 2025 using the
existing TranStats client. Only July records with positive departures were
placed into the separate research database; no production ingestion ran.

| Measured column | July 2025 control | July 2026 target | Raw delta |
|---|---:|---:|---:|
| Segment records | 49,558 | 47,890 | -3.37% |
| Distinct operating-carrier codes in rows | 264 | 235 | -10.98% |
| Nonstop segment passengers | 105,675,725 | 102,245,324 | -3.25% |
| Available seats | 126,938,108 | 123,203,380 | -2.94% |
| Departures performed | 985,404 | 969,998 | -1.56% |
| US-to-Canada directional rows | 784 | 728 | not yet reconciled |
| Canada-to-US directional rows | 788 | 732 | not yet reconciled |
| Exact duplicate rows | 1 | 0 | diagnostic only |
| Collisions at selected operator/route/equipment/class key | 89 | 78 | **do not deduplicate** |
| Records with neither airport in US | 0 | 0 | source scope confirmed on extracted sample |

The difference in operating-carrier code coverage (264 to 235) is material to
interpretation. It does **not** prove 29 operators stopped flying; a current
public release can withhold foreign-carrier filings or revise historical data.
Likewise, a -3.25% aggregate passenger delta is **not** evidence of a true
traffic decline. The source has filing and revision caveats, and the exercise
does not yet match a complete common-carrier panel.

The selected key drops dimensions of the original reporting record. The 78
collisions are a warning about grain, not 78 demonstrated duplicate flights.
Carrier mapping identified 3,868 records belonging to known multi-brand
operators (OO, YX, G7 and ZW), for which no marketing brand was invented.
Until missing carrier coverage, airport crosswalks and record grain are
resolved, this is a **useful negative data-quality finding**, not a screening
upgrade.

## Stable-ID follow-up and source-quality result

Independent run: [BTS stable-ID extraction and audit, run 40781581975](https://github.com/yumorepos/network-lab/actions/runs/40781581975).
The script requests the BTS-published OriginAirportID,
DestAirportID, OriginCityMarketID and DestCityMarketID directly from
table 293, then cross-checks stable IDs against current Master Coordinate.
Eight offline fixture tests passed, including negative controls.
The repository suite passed **90 tests**, with **141 warehouse-dependent skips**.

| July 2026 check | Verified value |
|---|---:|
| Observed airport-ID/city-market-ID pairs | 1,435 |
| Stable AirportIDs matched to Master Coordinate | **1,435 / 1,435** |
| Missing stable-ID matches | **0** |
| CityMarketID disagreements on stable-ID match | **0** |
| Airport codes missing from current lookup | **1: PBI** |
| July segment records touching PBI | **280** |
| Published July segment passengers touching PBI | **587,101** |
| Reused or ambiguous three-character codes in the full latest lookup | 18 |
| Ambiguous codes observed in July | ISL, SAW, T4X |
| July segment rows touching those codes | 6 |
| Stable AirportIDs with conflicting latest market ID | **0** |

**Independent explanation:** The West Palm Beach airport authority announced
the code change **PBI to DJT effective August 18, 2026**, after the
July T-100 measurement month. Air Canada's dated advisory corroborates it:
https://www.pbia.org/articles/post/president-donald-j-trump-international-airport-name-change-takes-effect/
https://www.aircanada.com/ie/en/ado/home/book/travel-news-and-updates/2026/airport-code-change-for-west-palm-beach.html

BTS explicitly warns that three-character codes can be changed or reused,
and recommends stable AirportID for analyses across time:
https://www.transtats.bts.gov/Fields.asp?gnoyr_VQ=FLL
Table 293 publishes AirportID and CityMarketID in its source record:
https://transtats.bts.gov/Fields.asp?gnoyr_VQ=FMG

**Finding:** A historical-to-current airport-code-only join can silently
exclude 280 rows carrying 587,101 nonstop segment passenger records for this
July snapshot. Direct stable-ID reconciliation resolves all observed airports
and finds no market-ID disagreement. The 18 ambiguous codes are not 18
proven source mistakes; the July subset touches three of them across six
segment rows. The stable IDs disambiguate these cases. No PBI-to-DJT code
substitution, arbitrary maximum city-market ID, or change to the production
warehouse is justified without a separately scoped versioned join review.

**Limits:** These are raw T-100 segment counts across reported service
classes, not ticket O&D or a validated passenger-service-only time series.
July 2025 is extracted from today's revised source, not a point-in-time
2025 vintage. Foreign-carrier filing completeness is not established,
and operating certificates cannot be assumed to equal marketing brands.
The verified BTS CityMarketID lookup does not validate the project's
separate CBSA/CMA metro mapping.

## Acceptance and stop decision

**Gate B: CLOSED as a documented data-quality result; STOP without model
adoption.** This is the roadmap's substantive source-quality lesson, not an
improved screening or predictive result.

- Production metric impact: **none evaluated**. No production data warehouse,
  modeling run, replay, assumptions, or dashboard artifacts were changed.
- Verdict movements: **none caused**. No LAUNCH/MONITOR/PASS adjustment
  is supported by this pilot.
- Statistical meaningfulness: **unresolved**. The raw -3.25% passenger and
  -10.98% carrier-code differences cannot identify a real year-over-year
  demand change until filing coverage, service class and comparable carrier
  cohorts are reconciled.
- Regression and data risk: 8 pilot unit tests plus full 90-test CI pass;
  the live source download succeeded, but the public release is revisable.
  These tests do not replace full warehouse reproducibility gates.
- Action: archive research diagnostics, leave published data untouched,
  and separately scope any versioned airport-ID join improvement.

Stage C, if pursued, is a separate DB1C schema-compatibility spike. T-100
nonstop passengers must not be substituted for DB1C ticket O&D demand.

**Closed status clarification:** The source-quality deliverable is complete.
A future production airport-identity fix requires a separately scoped
consumer-impact audit; no historical replay, 2018 StatCan anchor, model
assumption or `data/parquet/outputs` change was made in Stage B.
